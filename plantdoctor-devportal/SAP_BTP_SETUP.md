# PlantDoctor DevPortal - SAP BTP Integration Setup

## Overview
The PlantDoctor DevPortal now integrates with SAP BTP's Plant Issue OData V4 Service. After analyzing plant issues, you can automatically submit them to SAP BTP for workflow processing and tracking.

## Environment Variables

Configure these environment variables in your Cloud Run deployment or local `.env` file:

```bash
# SAP BTP Service Configuration
SAP_BTP_BASE_URL=https://t4x.wdisp.bosch.com/sap/opu/odata4/sap/ZUI_BTP_PLANTDOC_O4/srvd/sap/ZUI_BTP_PLANTDOC/0001/
SAP_BTP_USERNAME=your_sap_username
SAP_BTP_PASSWORD=your_sap_password

# Google Cloud Configuration (already set by deployment)
VERTEX_PROJECT_ID=plantdoctor-codingaura
VERTEX_LOCATION=asia-south1
```

## OData Service Details

### Base URL
```
https://t4x.wdisp.bosch.com/sap/opu/odata4/sap/ZUI_BTP_PLANTDOC_O4/srvd/sap/ZUI_BTP_PLANTDOC/0001/
```

### Main Entity: PlantDoc
- **Create Issue**: POST `/PlantDoc`
- **Read All Issues**: GET `/PlantDoc`
- **Read Single Issue**: GET `/PlantDoc(IssueId='<id>')`
- **Update Issue**: PATCH `/PlantDoc(IssueId='<id>')`

### Required Fields

| Field | Type | Description | Allowed Values |
|-------|------|-------------|-----------------|
| Plant | String | Plant/asset ID | e.g., "1000", "1001", "1002" |
| Rootcause | String | Root cause of the issue | e.g., "Machine overheating" |
| Solution | String | Proposed solution | e.g., "Cooling system inspection planned" |
| Status | String | Issue status | OPEN, IN_PROGRESS, COMPLETED |

### Optional Fields
- `IssueId`: Auto-generated by SAP BTP (do not send in create request)

## Workflow

### Step 1: Upload Report & Analyze
1. Go to **"📁 Upload Report (ZIP)"** tab
2. Upload a ZIP file containing:
   - JSON analysis reports (from Ollama, TensorFlow, etc.)
   - Log files with error details
3. Describe your investigation context
4. Click **"🚀 Send to Gemini for Analysis"**

### Step 2: Review Analysis Summary
The system extracts and displays:
- **Root Cause**: Identified problem
- **Solution**: Recommended fix
- **Status**: OPEN, IN_PROGRESS, or COMPLETED
- **Plant ID**: Target plant/asset identifier

### Step 3: Submit to SAP BTP
1. Review and adjust the analysis summary if needed
2. Optionally change the Plant ID
3. Click **"📤 Send to SAP BTP"**
4. System will create an issue record in SAP BTP
5. Success response includes the generated `IssueId`

## Setting Environment Variables

### Option 1: Cloud Run Deployment (Recommended)
Update the GitHub Actions workflow or use gcloud:

```bash
gcloud run services update plantdoctor-devportal \
  --region=asia-south1 \
  --project=plantdoctor-codingaura \
  --set-env-vars="SAP_BTP_BASE_URL=https://t4x.wdisp.bosch.com/sap/opu/odata4/sap/ZUI_BTP_PLANTDOC_O4/srvd/sap/ZUI_BTP_PLANTDOC/0001/,SAP_BTP_USERNAME=your_username,SAP_BTP_PASSWORD=your_password"
```

### Option 2: Local Development (.env file)
Create a `.env` file in the `plantdoctor-devportal` directory:

```bash
SAP_BTP_BASE_URL=https://t4x.wdisp.bosch.com/sap/opu/odata4/sap/ZUI_BTP_PLANTDOC_O4/srvd/sap/ZUI_BTP_PLANTDOC/0001/
SAP_BTP_USERNAME=your_sap_username
SAP_BTP_PASSWORD=your_sap_password
VERTEX_PROJECT_ID=plantdoctor-codingaura
VERTEX_LOCATION=asia-south1
```

Run locally:
```bash
cd plantdoctor-devportal
python -m streamlit run app.py
```

## Error Handling

| Error | Cause | Solution |
|-------|-------|----------|
| Cannot connect to SAP BTP | Wrong URL or network issue | Verify SAP_BTP_BASE_URL |
| 401 Unauthorized | Invalid credentials | Check SAP_BTP_USERNAME and SAP_BTP_PASSWORD |
| 403 Forbidden | No access to service | Request SAP admin to grant access |
| 400 Bad Request | Invalid payload format | Check that all required fields are populated |
| Timeout | SAP BTP slow response | Retry or check SAP system status |
